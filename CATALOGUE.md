# CATALOGUE — the page list that drives everything

Machine-parseable (see `scripts/catalogue.py`). Each `##` section is a category (= template name in `docs/_templates/`); each table row is one page.
Columns: `id | slug | title | path | code | diagrams | tier | weight | batch | links_to | scope`.
- `code`: comma-separated artifacts relative to the repo root (`-` = none). A trailing `/` means a package.
- `diagrams`: comma-separated required kinds (`flowchart`, `sequence`, `class`, `state`, `er`) and figures (`fig:name` = `docs/assets/img/figures/name.png`). Case studies always add the standard set (v1 flowchart, v2 flowchart, er, write sequence, read sequence).
- `tier`: P0 / P1 / P2. `weight`: S / M / L. `batch`: owning authoring batch (`GOLDEN` = written by the orchestrator, `PILOT-*` = pilot agents, `ORCH` = orchestrator).
- `links_to`: slugs this page must link in `## Related`.
- Long briefs for LLD problems live under `## Briefs`, keyed by id. Never use `|` inside a cell.

## Briefs

### LP-01
FR: multiple floors; spot types (motorcycle, compact, large, EV, handicapped); vehicle types; entry gate issues a ticket and assigns the nearest eligible spot; multiple entry and exit gates; exit computes the fee via a pricing strategy (hourly, flat, daily cap); payment (cash, card); per-floor availability display; admin adds and removes floors and spots; reject when full.
Entities: ParkingLot, ParkingFloor, ParkingSpot, SpotType, Vehicle (+ Car, Truck, Motorcycle, ElectricCar), Ticket, EntryGate, ExitGate, PricingStrategy, SpotAllocationStrategy, Payment, DisplayBoard.
Patterns: Singleton (lot), Factory (vehicles, spots), Strategy (pricing, allocation), Observer (display), State (ticket, spot).
